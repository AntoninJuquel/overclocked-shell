# Fashion wardrobes (E6) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (the player's usual flow) to implement
> this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The player drops a fashion screenshot (YouTube, r/DestinyFashion: shaders and ornaments listed per slot)
or a list; the Ghost reads it, and Shell says for each piece whether they own it and, if not, where it comes from and
whether Eververse sells it today; looks are saved as wardrobes and applied with the usual preview — story S-019.

**Spec:** the player's description, agreed in chat 2026-10-28 / 29: the hard part is "finding if I had it and if not
the sources"; inspiration comes as a screenshot like Trimedic13's Warlock look (shaders left column, ornaments right).

**Architecture:** One engine `shell/engines/fashion.py` (index the manifest's shaders / ornaments / armor by name,
resolve a look, ownership from Collections, source line, Eververse offer, the exotic an exotic ornament needs), one
tool module, one skill. Reading the screenshot is the Ghost's own vision — no OCR code. Applying uses the existing
`get_equipped` + `set_sockets` (plugs by name, previews). No core edits.

**Checked live 2026-10-29 (manifest + saved context):**
- Shaders: `plug.plugCategoryIdentifier == "shader"`. Ornaments: `armor_skins_<class>_<slot>`
  (`head|arms|chest|legs|class`), exotic ones `armor_skins_<class>_exotic_<slot>` (e.g. Electro-Brass).
  Same name across classes (Vigil of the Seraph: hunter / titan / warlock) → pick the character's class.
- Every one has a `collectibleHash`; `DestinyCollectibleDefinition.sourceString` gives "Source: Eververse",
  "Source: Season Pass Reward", "Source: Rewards Pass".
- Eververse (vendor 3361454721) sales are already in the raw weekly context (`profile/context/<date>.json`,
  224 offers, `nextRefreshDate`).

## Global Constraints

- Ownership = Collections (profile component 800): a collectible is owned when its state lacks bit 1
  (NotAcquired) in `profileCollectibles` or any character's `characterCollectibles`.
- Apply only cosmetics (ornament and shader sockets) through `set_sockets` previews; never mods, perks, stats.
- Inspiration is a screenshot or list the player gives; no Reddit / YouTube fetching (Reddit refuses automated
  fetches; its API needs the player's own app). The story's "inspiration fetched online" criterion becomes
  "inspiration from a screenshot or list the player gives".
- Tests: `uv run --no-sync pytest -q` while the MCP server runs.

## Rulings (player can override)

1. **Look format:** `[{"slot": "Helmet|Gauntlets|Chest|Legs|Class Item", "ornament": name?, "shader": name?}]` —
   the screenshot's two columns read row by row; the Ghost confirms the list with the player before checking.
2. **Name matching** case-insensitive, straight / curly apostrophes equal (`aegis.names.norm`). Unknown name → the
   row says "not found" with up to 3 close names (`difflib.get_close_matches`), never a guess.
3. **Armor pieces named instead of ornaments** (some looks use the base armor) are accepted: owned = in the
   inventory snapshot or Collections.
4. **Exotic ornaments** report the exotic they fit (found through the exotic's ornament plug set), and whether the
   player owns that exotic.
5. **Wardrobes:** `profile/fashion/<slug>.json` = `{name, class, look, credit?, saved}`; written only when the player
   asks to save.
6. **Eververse:** price from the newest raw context's Eververse sales (cost names from the manifest: Bright Dust,
   Silver); a context from a past week → "Eververse stock unknown (refresh_context)".

## Review Focus

1. Same ornament name in three classes → the character's class is chosen; a Hunter ornament asked on a Warlock →
   "not for Warlock".
2. A shader listed on every slot (Ceramic Alloy ×3) → checked once, reported per slot.
3. A collectible missing from the profile response (privacy setting, new item) → "unknown", not "missing".
4. No raw context or a stale one → ownership and sources still answered; Eververse line says why it is unknown.
5. A name that matches nothing → close names suggested; the rest of the look is still checked.

### Task 1: Fashion engine

**Files:** Create `shell/engines/fashion.py`; Test `tests/engines/test_fashion.py`.

**Interfaces — Produces:**
- `build_index(items: dict, collectibles: dict, plug_sets: dict) -> dict` — `{norm name: [entry]}`, entry =
  `{"hash", "name", "kind": "shader"|"ornament"|"armor", "cls": "Warlock"|...|None, "slot"?, "exotic_for"?,
  "collectible"?, "source"?}` (source = `sources.parse_source_string`-style first line without "Source: ").
- `resolve(name: str, kind: str, cls: str, index) -> tuple[entry | None, str | None]` — (entry, problem): problem
  is `"not for <cls>"` or `"not found (close: a, b)"`.
- `owned(entry, collectibles_state: dict[int, int], inventory_hashes: set[int]) -> bool | None` — None = unknown.
- `eververse(entry, raw_context: dict | None, now, items: dict) -> str` — "on sale: 1,500 Bright Dust until
  2026-11-03", "not on sale this week", or "stock unknown (refresh_context)".
- `check(look, cls, index, state, inventory_hashes, raw_context, now, items) -> dict` —
  `{"rows": [{"slot", "kind", "name", "owned", "source", "eververse", "exotic_for"?, "problem"?}],
  "summary": "7 of 10 owned; missing: …"}`.
