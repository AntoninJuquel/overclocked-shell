# Farm TODO (E4, part 3) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Shell tells the player what to farm tonight like dim-agent — farm needs from the build sheets and Aegis's Shopping List, the week's context (Portal focus, bonuses, vendor sales), a dated TODO ranked by gain × availability, and statuses — story S-015, with the same ranking as dim-agent on the same data.

**Architecture:** Port, don't rewrite. dim-agent's `scripts/todo/` becomes `shell/engines/todo/` (logic unchanged; imports, paths, manifest access and language change); `context.py` is renamed `week.py` (Shell already has `shell/engines/context.py`, which builds the raw context). Each CLI becomes an MCP tool in its own module. Inputs are Shell's inventory snapshot, the raw context `refresh_context` saves (destiny-zen's `zen-context` shape), the build sheets, the build catalog and Aegis; manifest tables (items, collectibles, milestones, activities, modifiers, vendors) are read with `Manifest.table(name, keep=False)` per call, as dim-agent read them per run.

**Tech Stack:** Python 3.12, `shell.engines.builds` (inventory, mods, optimize, sheet, stats, catalog, snapshot), `shell.sources.aegis`, `shell.core.Manifest`, `mcp` 2.3 via `shell.mcp.tool`.

**Spec:** `docs/specs/2026-10-28-overclocked-shell-design.md`. Behaviour reference (parity, read-only): `D:\Projects\dim-agent\scripts\todo\*.py`, `tests\test_todo_*.py`, `.claude\skills\todo\SKILL.md`, the player's `todo\` files.

## Global Constraints

- Everything English: need labels and effects, warnings, the plan Markdown (sections **This week** / **When you can** / **Later**, "Week until … · Focus: …", "For:", "Where:", footer "Ignored: n · Done: n"), tool output, the skill. Numbers in the Markdown use a decimal point.
- Data values kept exactly, so the player's files keep working: statuses `todo` / `done` / `ignored`; boosts `focus` / `bonus` / `sale`; source types `activity` / `vendor` / `craft` / `world`; kinds `armor` / `masterwork` / `weapon` / `catalyst` / `upgrade` / `aegis`; the build `aegis`; every id format (`armor/<cls>/<slot>/<set|->/<arch+arch>/<tert+tert|*>`, `masterwork/<itemId>`, `<kind>/<slug>`, `aegis/<slug>`).
- Paths: `profile/todo/` holds `needs.json`, `state.json`, `overrides.json`, `sources.json` and the dated plans `<date>[-<build>].{json,md}`; the processed week goes to `profile/todo/week/<date>.json` (the raw context stays in `profile/context/<date>.json`, written by `refresh_context`).
- Set bonuses come from the catalog (`"2 pieces: X"`); code reading them keeps parsing the leading count only.
- No core edits. New code in `shell/engines/todo/`, `shell/mcp/tools/`, `.claude/skills/todo/`, `tests/`.
- Writes only to `profile/` and `cache/`; nothing touches the account.

## Rulings in this plan (player can override)

1. **No new cache.** Manifest tables are read per call (the item table took ~5 s in the catalog build); the TODO runs a few times a week.
2. **Tools replace scripts:** `farm_needs(no_aegis=False)`, `week_context()`, `farm_plan(build=None, top=10)`, `set_need_status(need_id, status, note=None)`. `farm_needs` re-saves every sheet (their "To fetch" section), as `needs.py` did.
3. **`week_context` reads the newest raw context** in `profile/context/`; the skill calls `refresh_context(character)` first (as it called `export_context`).
4. **The dated plan JSON stores English section names**; old French plan files are history, nothing reads them back.

## Review Focus

1. **A partial run** (no weapon snapshot, no Aegis data, a sheet without resolved armor) → needs that could not be checked are not auto-marked done (`complete` / `keep` logic), and a warning says what was skipped. (Task 3)
2. **A need id the player marked done or ignored** reappears in `needs.json` → its status stays; an auto-done need that reappears goes back to todo. (Tasks 1, 3)
3. **The raw context is from last week** → `farm_plan` ignores it (no boosted section) and says the week is unknown; `week_context` tells to call `refresh_context`. (Tasks 2, 4)
4. **An `overrides.json` entry with a past `until`** → skipped; a date-only `until` lasts to 23:59:59 UTC that day. (Task 2)
5. **`set_need_status` on an unknown id** → one-line error listing nothing changed; a typo never creates a phantom entry. (Task 4)
